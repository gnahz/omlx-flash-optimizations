# Release validation

[中文](VALIDATION.zh-CN.md)

Historical performance figures are in `results/published/`; this file describes checks of the portable package and does not label an unrun workload as validated.

Completed component checks:

- DeepSeek driver/launcher: **17 CPU tests passed**, including complete SSE/error evidence, frozen payload checksums, exact geometry construction, full ABBA/warmup accounting, bulk-versus-tail counter checks, output/counter identity, localhost authorization and active-request control guards, separate cache profiles, fresh config keys, removal of ambient engine/auth flags, service-owned cluster shim/reaper state, and bounded startup connection retries that leave auth/HTTP failures immediate. Both `--help` paths require no MLX import.
- The real pinned CPU tokenizer/formatter reproduces all three 8192-token frozen requests and deterministic case-0 requests at 16384, 32768 and 8242 tokens. No model or HTTP request was used for this check.
- DeepSeek actual-weight GPU component check: **1,218 cases and 40 controls passed with zero BF16 mismatch**, covering selected actual expert banks at layers 0/19/39, metadata decoding and native dictionary prefill against the original NAX oracle. Peak MLX allocation was 301,542,446 bytes. This loads selected weight slices, not the full model, and measures no model throughput. See [`actual-metadata-prefill.json`](../results/qualification/deepseek/actual-metadata-prefill.json) and [`validator-provenance.json`](../results/qualification/deepseek/validator-provenance.json).
- DeepSeek full-model replay: **all 42 requests passed**, covering exact 8K three-case and 16K/32K case-0 protocols. The 32 measured requests generated 16,384 tokens after ten discarded warmups, with zero prefix reuse, complete output/non-timing DSpark identity, A dense/B direct bulk-path checks, stable process/source/proof identity and restored prefill controls. Complete request/SSE/output evidence and original report hashes are in [`full-core`](../results/qualification/deepseek/full-core/manifest.json). Background Hub upload and host workload were active, so these new timings are qualification evidence rather than replacements for the archived headline results. Physical footprint was not independently sampled by this HTTP driver.
- DeepSeek cached/restart acceptance: **both ten-request probes passed**, at 8242 prompt / 64 output tokens with identical complete outputs, 8192 reused warm/parallel tokens and eight observed running requests. Orderly shutdown saved one checkpoint; a different process restored the same generation with zero restore failures and reused 8192 tokens on its first request. There were two cache disk reads at startup. See the sanitized [`cache evidence`](../results/qualification/deepseek/cache/manifest.json), [`restart acceptance`](../results/qualification/deepseek/cache/restart-acceptance.json) and [`shutdown receipt`](../results/qualification/deepseek/cache/cache-shutdown-first.json). This does not qualify full-cache saturation, maximum-length eight-request capacity, sustained throughput or sampled physical footprint.
- Qwen: independent baseline and optimized native builds, pip checks, the original **62 cache tests** and **14 policy tests**, and **49 release CPU tests with 24 subtests** passed. All six ordered patches and the four-patch baseline apply from the fixed base. The common startup-isolation patch was applied to both prepared editable source trees after their native builds; native binaries/dependencies were unchanged. Native kernel-group availability, source-policy relocation, full source/native identity checks and 24 archived task-contract outputs were checked. See `profiles/qwen/validation.json`. The final combined release CPU run passed **75 tests with 24 subtests**.
- Qwen full-model protocols: **111 accepted requests / 86 measurements** across completed core r2 (36), passed tasks r3 (24) and passed prefix r3 (51). Core requests verified exact 2K/8K/32K inputs, 512 outputs and zero cached tokens; tasks reproduced the complete archived outputs and AST/JSON contracts. Prefix comparisons and all seven JSON semantic replays passed; optimized public-prefix C/D/E reused 2048 tokens, and the last two semantic warm replays reused 2126. Complete request/output/SSE, actual metrics, identities and original hashes are in the [`protocol manifest`](../results/qualification/qwen/protocol-manifest.json). The original r2 **whole invocation remains failed** after its completed core jobs, owing to an inapplicable short-task bulk-NAX log assertion. Its old cache-clear path logged 31 SSD ENOENT errors, so r2 is not claimed as clean SSD acceptance. The four fresh r3 jobs passed with zero ERROR/ENOENT lines using native availability preflight and stable writer drain outside request timing. Full source/native identity checks also run outside timing. The 1344/880-token tasks are below the 2048-token bulk-dispatch floor and use normal short routes; eligible core/prefix jobs still require observed NAX dispatch. See the [evidence explanation](../results/qualification/qwen/README.md).
- Qwen upstream weights: **42 files verified** at revision `e171af86f499f1855b0fb71d781105e8dd609610` with `hf cache verify --fail-on-missing-files`; no extra model payload was found. See [`upstream-weight-verification.json`](../results/qualification/qwen/upstream-weight-verification.json).

- DeepSeek Hub release: **262 release files verified** at public revision `09bc1b6f5a74c888ffc20cad1c66a197cdec6065`, totaling 451,545,010,970 bytes. All 250 large-file LFS SHA256 values and sizes match the complete local content hashes; all 12 regular files were downloaded and hashed. The remote file set matches the release plus Hub-managed `.gitattributes`. This does not claim a second full 420.53 GiB download. See the [file-by-file verification](../results/qualification/deepseek/hub-release-verification.json) and [fixed release metadata](../profiles/release.json).

New model-run timings were obtained with background Hub upload/host workload and stay separate from the archived speeds. The DeepSeek download command requires a verified revision in `profiles/release.json` and rejects missing/unverified release metadata.

The release benchmark protocols retain complete outputs and failures; they do not certify full-logit equivalence, original quantizer accuracy, between-sample memory peaks, or successful completion of the synthetic engineering requests as agent projects.
